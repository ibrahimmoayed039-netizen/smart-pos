# نظام نقطة البيع — نسخة Electron (سطح مكتب)

هذا المشروع يحوّل واجهتك إلى تطبيق ويندوز بنافذة خاصة و`.exe`، مع مثبّت
احترافي (معالج فيه صفحة ترخيص + اختيار مجلد + اختصارات) تماماً مثل
«البائع الذكي». الناتج النهائي يُثبّت على أي جهاز ويندوز بضغطة زر.

## محتويات المشروع
- `main.js`           ← العملية الرئيسية (تفتح النافذة وتحمّل الواجهة)
- `POS_System.html`   ← واجهة برنامجك (منسوخة كما هي)
- `package.json`      ← إعدادات التطبيق والمثبّت (electron-builder)
- `license.txt`       ← نص الترخيص الذي يظهر في المعالج
- `build/icon.ico`    ← (تضعه أنت) أيقونة البرنامج

---

## المتطلبات (مرة واحدة على جهاز ويندوز)
1. ثبّت **Node.js** نسخة LTS من: https://nodejs.org
2. (اختياري) ضع أيقونتك باسم `icon.ico` داخل مجلّد `build`.
   إن لم تضعها، سيُبنى البرنامج بأيقونة Electron الافتراضية.

---

## التشغيل التجريبي (لرؤية البرنامج قبل البناء)
افتح موجّه الأوامر (CMD) داخل مجلّد المشروع ونفّذ:

```
npm install
npm start
```

ستظهر نافذة البرنامج. أغلقها عند الانتهاء.

---

## بناء المثبّت النهائي (Setup.exe)
في نفس المجلّد نفّذ:

```
npm run dist
```

بعد انتهاء العملية ستجد المثبّت داخل مجلّد:

```
dist\نظام نقطة البيع Setup 1.0.0.exe
```

هذا الملف:
- يفتح معالج تثبيت فيه صفحة الترخيص وزر «I Agree» مثل الصورة.
- يثبّت البرنامج في `AppData\Local\Programs` (نفس مكان «البائع الذكي»).
- ينشئ اختصاراً على سطح المكتب وفي قائمة ابدأ.
- يضيف أداة إزالة تثبيت (Uninstall).

## 🐙 بناء المثبّت عبر GitHub (بدون الحاجة لجهاز ويندوز عندك)

المشروع يحتوي ملف `.github/workflows/build.yml` يجعل GitHub نفسه يبني
لك `Setup.exe` تلقائياً على خوادمه (مجاني)، حتى لو كان جهازك ماك أو
لينكس أو حتى موبايل.

### الإعداد أول مرة
1. أنشئ مستودع (Repository) جديد فارغ على github.com (خاص أو عام).
2. ارفع محتويات هذا المجلد إليه:
   ```
   git init
   git add .
   git commit -m "نظام نقطة البيع"
   git branch -M main
   git remote add origin https://github.com/USERNAME/REPO.git
   git push -u origin main
   ```
   (لا تقلق بخصوص `node_modules` أو `dist` — ملف `.gitignore` يستثنيهما تلقائياً).

### كل مرة تريد نسخة تثبيت جديدة
- **الطريقة السريعة (Artifact تجريبي)**: أي `git push` على `main` يشغّل
  البناء تلقائياً. من تبويب **Actions** بالمستودع ← افتح آخر تشغيل
  (Run) ← بعد اكتماله (حوالي 3-5 دقائق) ستجد **POS-Setup-Windows** في
  أسفل الصفحة تحت "Artifacts" ← نزّله (ملف zip يحوي الـ exe بداخله).
  ⚠ الـ Artifacts تُحذف تلقائياً بعد 30 يوماً.

- **الطريقة الرسمية (Release دائم)**: لإصدار ثابت لا ينتهي، أنشئ تاق
  بصيغة إصدار:
  ```
  git tag v1.0.0
  git push origin v1.0.0
  ```
  سينشئ GitHub تلقائياً **Release** جديد في تبويب **Releases** بالمستودع،
  مرفق فيه ملف `Setup.exe` جاهزاً كرابط تحميل دائم تقدر تشاركه مع
  العملاء مباشرة.

- **تشغيل يدوي بدون تعديل كود**: من تبويب **Actions** ← اختر
  "بناء نسخة Windows" ← **Run workflow** لبناء نسخة فورية بدون أي `push`.

### ملاحظة
كل تعديل تطلبه مني على الكود لاحقاً، فقط اعمل `git push` للتعديلات
الجديدة (أو ابعت لي الملفات المحدّثة وسأرفعها لك)، وسيبني GitHub نسخة
Setup.exe جديدة تلقائياً بدون أي خطوة إضافية منك.

## 🖧 ربط عدة أجهزة (خادم رئيسي + عملاء) — على نفس الشبكة أو عبر VPN

نفس ملف التثبيت (Setup.exe) يعمل بوضعين، يختارهما المستخدم من شاشة تظهر
تلقائياً أول مرة (ويمكن فتحها لاحقاً من قائمة **الشبكة ← إعدادات الاتصال
بين الأجهزة** أعلى نافذة البرنامج):

- **خادم رئيسي**: يُثبّت على جهاز أول كاشير. يحفظ كل البيانات، ويشغّل
  خادماً داخلياً على المنفذ 5000، وتَظهر له عناوين IP الجاهزة ليعطيها
  لبقية الأجهزة.
- **عميل (فرع/كاشير)**: يُثبّت على بقية الأجهزة، ويُدخل فيه المستخدم
  عنوان IP الخاص بالخادم فقط، فيتصل به ويعمل بنفس البيانات لحظياً
  (كل عملية بيع أو تعديل تظهر تلقائياً عند الجميع خلال ثوانٍ).

### الحالة 1: كل الأجهزة في نفس المكان (نفس الواي فاي / نفس الراوتر)
لا حاجة لأي برنامج إضافي — فقط أعطِ الفروع عنوان **الشبكة المحلية (LAN)**
الظاهر في شاشة إعدادات الخادم (مثل `192.168.1.10`).

### الحالة 2: فروع في أماكن مختلفة — عبر Radmin VPN
1. حمّل **Radmin VPN** من radmin-vpn.com وثبّته على جهاز الخادم وكل فرع.
2. من جهاز الخادم: أنشئ شبكة جديدة (Network) وشارك اسمها وكلمة مرورها.
3. من كل جهاز فرع: انضم لنفس الشبكة بنفس الاسم وكلمة المرور.
4. في شاشة إعدادات الخادم بالبرنامج، اختر تبويب **Radmin VPN** وانسخ
   العنوان الظاهر هناك (يبدأ عادة بـ `26.x.x.x`)، وأدخله في وضع
   «عميل» بجهاز الفرع.

### الحالة 3: فروع في أماكن مختلفة — عبر Tailscale
1. حمّل **Tailscale** من tailscale.com وثبّته على جهاز الخادم وكل فرع.
2. سجّل الدخول بنفس الحساب على جميع الأجهزة (يصبحوا على نفس الـ Tailnet).
3. في شاشة إعدادات الخادم بالبرنامج، اختر تبويب **Tailscale** وانسخ
   العنوان الظاهر (يبدأ عادة بـ `100.x.x.x`)، وأدخله في وضع «عميل»
   بجهاز الفرع.

### ملاحظات مهمة
- اترك جهاز الخادم الرئيسي **يعمل دائماً** أثناء ساعات العمل؛ إذا أُغلق
  البرنامج فيه تتوقف بقية الأجهزة عن التحديث حتى يُعاد فتحه.
- عند أول تشغيل لوضع «خادم»، قد يسأل *جدار حماية ويندوز*
  (Windows Firewall) عن السماح للبرنامج — اختر «السماح» (Allow access)
  حتى تصل الأجهزة الأخرى إليه.
- المنفذ الافتراضي هو `5000`، ويمكن تغييره من نفس شاشة الإعدادات لو
  كان مستخدَماً من برنامج آخر.
- زر «اختبار الاتصال» في وضع «عميل» يتأكد فوراً هل الجهاز يصل للخادم
  أم لا، قبل حفظ الإعداد.
- إذا احتجت وضع الخادم على جهاز/حاسوب منفصل بدون تثبيت واجهة كاملة
  (مثلاً NAS)، ملف `server.js` نفسه يعمل مستقلاً بأمر `node server.js`
  دون Electron، بنفس منطق المزامنة.

## 🛡️ النسخ الاحتياطي — لو توقف الخادم الرئيسي

### 1) استمرارية فورية (تلقائية، بلا إعداد)
لو انقطع الاتصال بالخادم مؤقتاً (تعطّل، إعادة تشغيل، انقطاع شبكة)،
تستمر أجهزة الفروع بالعمل عادي بأحدث بيانات وصلتها، وتُراكم أي عملية
بيع أو تعديل جديد في قائمة انتظار محفوظة على نفس الجهاز. بمجرد عودة
الاتصال تُرسل هذه التغييرات تلقائياً خلال ثوانٍ — لا حاجة لأي تدخل.
شارة صغيرة أسفل يسار الشاشة (🟢 متصل / 🔴 غير متصل) تُظهر الحالة لحظياً.

### 2) نسخ احتياطية دورية
- **الخادم الرئيسي** يأخذ نسخة احتياطية تلقائية عند كل تشغيل، ثم كل
  10 دقائق كحد أقصى عند وجود تغييرات، ويحتفظ بآخر 30 نسخة.
- **جهاز عميل** يمكن تفعيل خاصية **"نسخة احتياطية محلية تلقائية"** له
  من شاشة إعدادات الاتصال (checkbox في وضع «عميل»)، فيسحب نسخة كاملة
  من بيانات الخادم كل دقيقتين ويحفظها محلياً على نفس الجهاز.
- كل النسخ تُدار من نافذة **الشبكة ← النسخ الاحتياطي**: عرض القائمة،
  إنشاء نسخة يدوياً الآن، تصدير أي نسخة كملف (لحفظها في USB مثلاً).

### 3) لو تعطّل الخادم الرئيسي نهائياً (عطل جهاز/هارد)
على أي جهاز عميل كانت خاصية "النسخة الاحتياطية المحلية" مفعّلة عليه:
1. افتح **الشبكة ← النسخ الاحتياطي**.
2. اختر أحدث نسخة، واضغط **"🚀 ترقية لخادم"**.
3. سيتحول هذا الجهاز فوراً إلى خادم رئيسي بنفس البيانات (حتى لحظة آخر
   نسخة سُحبت)، ويعاد تشغيله تلقائياً.
4. لا تنسَ تحديث عنوان IP الجديد في إعدادات بقية أجهزة الفروع ليتصلوا
   بالخادم الجديد بدل القديم.

هذه الطريقة تضمن أقصى فقدان بيانات محتمل بحدود دقيقتين (فترة المرآة
التلقائية) في أسوأ الحالات، وليس فقدان كل شيء.

## ☁ إعداد النسخ الاحتياطي السحابي (اختياري)

النظام يرفع نسخة JSON إلى أي رابط يستقبلها عبر POST ويعيدها عبر GET.
أسهل طريقة مجانية = Google Apps Script:

1. افتح https://script.google.com ← مشروع جديد، والصق هذا الكود:

```javascript
const KEY = 'ضع_كلمة_سر';            // نفس «مفتاح الحماية» في البرنامج
const FILE = 'pos-cloud-backup.json';

function getFile_(){
  const it = DriveApp.getFilesByName(FILE);
  return it.hasNext() ? it.next() : DriveApp.createFile(FILE, '{}', 'application/json');
}
function doPost(e){
  const body = JSON.parse(e.postData.contents || '{}');
  if (KEY && body.key !== KEY) return ContentService.createTextOutput('bad key');
  getFile_().setContent(typeof body.data==='string'?body.data:JSON.stringify(body.data));
  return ContentService.createTextOutput('ok');
}
function doGet(e){
  if (KEY && (e.parameter.key||'') !== KEY) return ContentService.createTextOutput('{}');
  return ContentService.createTextOutput(getFile_().getBlob().getDataAsString())
         .setMimeType(ContentService.MimeType.JSON);
}
```

2. Deploy ← New deployment ← نوع Web app ← Execute as: Me ← Who has access: Anyone ← انسخ الرابط (ينتهي بـ `/exec`).
3. في البرنامج: الإعدادات ← النسخ السحابي ← الصق الرابط ومفتاح الحماية ← حفظ.
4. استخدم «رفع الآن» / «استرجاع من السحابة»، أو فعّل «رفع تلقائي يومي».

البيانات تُحفظ في Google Drive الخاص بك في ملف `pos-cloud-backup.json`.
